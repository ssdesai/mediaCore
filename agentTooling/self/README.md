# self

agentTooling's own plan corpus — the harness applied to itself. This is the exact
counterpart of a consuming repo's `plans/` directory, one level in, and it is drained by
passing `--self` to the runners:

```bash
./agentTooling/run-batch.sh --self <slug>    # build, verify, review — and the close on a clean round
./agentTooling/run-plans.sh --self <slug>    # build pass only
./agentTooling/run-verify.sh --self <slug>   # verify pass only
./agentTooling/run-review.sh --self <slug>   # review pass only: the round's verdict, and nothing after it
./agentTooling/feature-close.sh --self <slug>  # PR, capture, merge request — from the worktree
```

| Path | What it is |
|---|---|
| `features/` | One directory per agentTooling feature: manifest, `auto/`, `verify/`, `review/`, `interactive/`, the JSON cost artifacts, and `routing.json` — the record of the **router** session that started it. See `features/README.md`. |
| `interactive/` | Standing runbooks that outlive any one feature. A feature's own bash-heavy steps live in `features/<slug>/interactive/` instead. |
| `BACKLOG.md` | What a finished feature found and deliberately left — one bullet each, phrased as the assertion that would catch it, with the feature that raised it. The counterpart of a consuming repo's `plans/BACKLOG.md`. An entry is removed by the feature that closes it, not when it is merely noticed again. |
| `PROJECT_FACTS.md` | The facts every agentTooling plan must pin — bash version, what stands in for a test runner, how the analysis scripts import each other. Read before authoring. |
| `gate.sh` | The mechanical gate `run-batch.sh --self` runs after the build pass, writing `gate-report.txt` for the verify and review passes to read. Syntax checks, the behavioural scripts in `tests/`, and one check that is neither: `hooks/wire-settings.py --self --check`, which compares the committed `../.claude/settings.json` **byte for byte** with what a fresh `--self --write` generates and names where they first differ — that file is generated, not merged, so a hand-added allow rule or a repointed hook command fails the gate exactly as a missing deny rule does. |
| `tests/` | Behavioural checks the gate `record`s — the runner contracts (`level-sentinel.sh`, `tiered-gates.sh`), the feature lifecycle's (`feature-lifecycle.sh`: start — pinning nothing, committing a routing record, pruning the features that have merged, `--open` — the stub-brief refusal, the capture on the branch and its push, the review pass's verdict (clean, escalated, unreadable — the round's commit, its `plan_end` details and the rework brief it writes), rounds across a rework, the close's five refusals and its order (PR → stamp → cost records pushed → merge request, with the origin head at the merge already carrying the record) and its re-runnability, `run-batch.sh` ending a round either way, `PR_AUTO_MERGE` behind `--merge-request` (`--merge`, never `--squash`), the prune after a merge, the post-merge repair and legacy captures, the window stamped from evidence rather than from the capture's clock, the residue the capture prints where the weekly sweep used to (rates, unclaimed sessions and delegates, routers excluded), the frozen-record annotation it makes at capture, and the runner's own commit of the pass — and none on the base branch; `routing-record.sh`: the routing record's derivation, its two readers and the capture's refresh; `capture-from-worktree.sh`: a worktree's copy of the capture selecting what the primary's would; `recover-at-close.sh`: the capture pricing what the CLI never did), the cost tooling's (`cost-recovery.sh`, `capture-guard.sh`, `subagent-capture.sh`, `timestamps-are-utc.sh`), the plan-linting's (`check-plans.sh`, whose check 7 now covers window ordering as well as the zone), the update-sync's (`sync-check.sh`), the two audit fixes with no other home (`audit-fixes.sh`: `report.py --all` writing the report of a feature that had none, and `run-batch.sh` linting a slug the build pass inferred), the direct build's milestone record (`direct-timing.sh`), the stale-sidecar contract (`stale-failed-sidecars.sh`: a retried plan's leftover `failed/` pair does not crash or skew the cost report), the stream capture's (`stream-capture.sh`), the hard-killed session's usage-limit routing (`usage-limit-kill.sh`), the batch's survival of a closed stdout (`batch-sigpipe.sh`), the two cost/time tables' marks for a figure nobody recorded (`report-footnotes.sh`), the Rounds table and its verdicts (`report-rounds.sh`), the template version/hash table (`template-versions.sh`, the one that reads the checked-in tree instead of a sandbox), the session opener's body (`open-session.sh`: both copies run with `osascript` and `claude` stubbed, a worktree path holding a space, `'`, `"` and `\` reaching the session intact through both escaping layers), the auto-approve hook's (`allow-repo-commands.sh`: every audited bypass refused, a chained `cd` and every ref-moving git command denied with their fixes, the harness's own entry points approved when the word carries a directory component, simple brace lists approved, a line that will not tokenize denied; `hook-wiring.sh`: the settings merge adds and never removes in a consuming repo, and `--self` is generated and checked byte for byte; `policy-table.sh`: the one git table renders a prefix rule for every mutating entry and the hook's own reader denies each one), and the corpus's plan numbering (`plan-numbering.sh`: the next stem continues the sequence past 99). See `tests/README.md`. |
| `pr.sh` | The forge side of `../feature-close.sh --self`, at `template-version: 4` with two entry points: `pr.sh <slug> <body-file>` pushes the branch and opens the PR (before `../feature-capture.sh` commits the cost records on it), and `pr.sh --merge-request <slug>` asks the forge to merge the PR already open — which the close calls last, after the capture has pushed. agentTooling's own copy of `templates/plans/pr.sh`; not written by `sync-plans.sh`, so keep it in step by hand when the template changes (`tests/sync-check.sh` 8 and `tests/template-versions.sh` assert the version, `tests/feature-lifecycle.sh` P1d that the two carry identical logic below their REPO-SPECIFIC line). Its one deliberate difference sits above that line: `AUTO_MERGE=0` whatever `PR_AUTO_MERGE` says, so `--merge-request` here only ever reports that auto-merge is off — a change in this directory ships to every consuming repo, and a human reads the PR before it merges. |
| `worktree-setup.sh` | The setup hook `../feature-start.sh --self` runs inside a new feature worktree, before the gate. agentTooling's own counterpart of `templates/plans/worktree-setup.sh`; it does nothing, because this repo is bash and stdlib Python with no install step — it exists so the hook path is the same in both modes. |
| `open-session.sh` | The hook `../feature-start.sh --self --open` runs to put a coordinator session inside the new worktree, with the worktree path as its only argument. agentTooling's own counterpart of `templates/plans/open-session.sh`, carrying the same `template-version` — **3** (asserted by `tests/sync-check.sh` and `tests/template-versions.sh`); it opens a Terminal.app window running `claude`. The one file here that may spell `cd <path> && <command>` — that string is handed to Terminal.app, not to the Bash tool, and its header says so. **The path crosses two named escaping layers on the way**, `shell_single_quote` (`'` → `'\''`) then `applescript_escape` (`\` → `\\`, `"` → `\"`), because it is written into a shell command line which is itself written into an AppleScript string literal. Version 2 had the first layer only, as a bare pair of quotes, so a worktree path holding `'`, `"` or `\` opened the session in the wrong directory or in none — and a session is billed to the branch of the directory it was launched in, so the mistake was silent and landed in the ledger as somebody else's money (`DESIGN-2026-09-18-minutes-slug-and-quoting.md` §3). `tests/open-session.sh` runs the body of both copies with `osascript` and `claude` stubbed and checks such a path arrives intact; `tests/feature-lifecycle.sh` S5c–S5f read both copies as text. |

Moved here because every fix lands in this directory; the input for the `feature-execution-procedure` self feature. |

Also holds the remaining steps for `permissions-policy-inherit`, the last feature closed under the old flow. |

Twelve numbered decisions, the acceptance tests, and the build shape. |
| `DESIGN-2026-09-18-ledger-and-routing.md` | Design record for the `ledger-and-routing` feature: the routing record moved from `<corpus>/routing/<session-id>.json` (an add/add conflict between any two features one router starts) to `<features>/<slug>/routing.json`, one per feature, with `routing.load_records` keeping the latest `captured_at` per router and `routing.py --migrate` moving legacy records; an open co-claimant bounded provisionally by its own `last_branch_instant`; every pinned or selected delegate written to the ledger even at $0; and `manifest.py set-window-from` as the tool the unclaimed-head warning names. Four defects, the assertions, and the two-slice build. |
| `DESIGN-2026-09-18-minutes-slug-and-quoting.md` | Design record for the `minutes-slug-and-quoting` sweep: a plan's minutes walked per attempt the way its dollars are (measured, recovered, unmeasured; a mixed cell is a lower bound); `slug_of_start_command` reading the slug from the start's own line after joining `\`-continuations; `open-session.sh`'s path escaped through both the shell and AppleScript layers (template-version 3); a report read that no longer rewrites the record when only `generated_at` would move; and two hook shapes read wrong (a single-quoted backtick is not a substitution, `git -C <in-root>` is judged by its subcommand). Five defects, the assertions, one implementer. |
| `DESIGN-2026-09-18-hook-rewrite-or-ask.md` | Design record for the `hook-rewrite-or-ask` feature: the permission hook's approval analysis returns one of three verdicts — REWRITE (a command it could not read and can name the rewrite for: denied with the rewrite, through the existing escalation), ASK (a command it read and cannot vouch for: a silent prompt, so the settings and the human decide), ALLOW — with any REWRITE member making the line REWRITE; the rewritable shapes (`$NAME`, `~`, a refused brace group, a `..` path component, a relative `cd`, a line break, a sequence mixing reads with one write); `unquoted_index` tracking both quotes; and the coordinator's shell rules moved into `CONVENTIONS.md` § Shell commands as guidelines. The assertions, the 24-command replay fixture, one implementer, an opus review. |
| `gate-report.txt` | Gate output. Gitignored — regenerated every batch. |
| `review-report.md` | The review pass's verdict, whose **first line** is `Verdict: clean` or `Verdict: escalated` — what `../run-review.sh --self` reads to end the round — and which `../feature-close.sh` uses verbatim as the PR body, with the Rounds table under it. On an escalated round the runner copies it to `features/<slug>/escalations/<review-stem>.md`, where it is the rework brief. Gitignored — regenerated every batch. |

## Not generated

A consuming repo's `plans/` stubs are written by `sync-plans.sh` from `templates/`, and
every one of them points back up at `../agentTooling/…`. From here those relative paths
are wrong and the "edit the template, not this file" banner would be a lie — this
directory *is* the source. Everything here is hand-written and stays that way;
`sync-plans.sh` does not touch it and takes no `--self` flag.

## Why costs land here, not in the host repo

A feature whose entire diff is under `agentTooling/` should carry its manifest, plans,
logs and cost records under `agentTooling/` too. Filing them in whichever repo happened
to vendor the subtree misattributes the work and strands it there — the next repo to
vendor agentTooling would have to recreate the history by hand. `plan-analytics` is the
worked example: it changed nothing outside this directory, and it lives here.

The execution model itself — state folders, resume semantics, the progress and usage
logs, how to read a failure — is documented once in `../RUNNER.md`, not repeated here.
