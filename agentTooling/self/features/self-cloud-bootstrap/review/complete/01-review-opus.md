# 01 — review: self-cloud-bootstrap

## What the feature was supposed to do

Close the `self/BACKLOG.md` entry "A fresh agentTooling cloud container is not born with
its settings file." A brand-new agentTooling session — a cloud container with nothing in
the environment's setup script, or a fresh clone anywhere — must come up with the
permission hook and the deny/ask rules loaded **from its first tool call**, with no step
outside the repo and no `feature-start.sh --self` first.

The proposed design (a tracked bootstrap whose `SessionStart` hook generates the policy
into an untracked `settings.local.json`) was built in round 1 (`2ed6b67`) and then
**replaced on live evidence** — `NOTES.md` → "The open question (live)": a policy written
during startup reloads asynchronously and missed the first tool call in 3 of 15 fresh
headless sessions; and a vendored `agentTooling/.claude/settings.json` is loaded only by a
session launched inside `agentTooling/`, where every path it names exists. So the design
judged here is the brief's fallback:

1. `.claude/settings.json` is **tracked** and is the whole `--self` policy (the
   `PreToolUse` hook, `Edit`/`Bash` deny, `hooks/` ask, sandbox block), generated by
   `hooks/wire-settings.py --self --write` and never hand-written. Its hook command is
   guarded: a no-op (exit 0, no output) when `${CLAUDE_PROJECT_DIR}/hooks/allow-repo-commands.sh`
   does not exist.
2. No `SessionStart` entry and no generated `settings.local.json` under `--self`;
   `.claude/settings.local.json` is git-ignored as Claude Code's own per-user file.
3. `--check` compares the tracked file byte for byte and names the regenerate command;
   `self/gate.sh`, `self/worktree-setup.sh` and `feature-start.sh --self` no longer
   generate an untracked file.
4. The backlog entry is removed; the "fix is a settings change" wording is rewritten in
   design §10, `templates/README.md`, `self/PROJECT_FACTS.md`; design §10 carries the
   findings.

## Contracts to hold it to

- `git ls-files .claude` lists exactly `.claude/settings.json`; it is byte for byte what
  `wire-settings.py --self --write` generates into an empty directory; it carries no
  `permissions.allow` and no `SessionStart` entry. `.claude/settings.local.json` is ignored.
- The tracked hook command, run as Claude Code runs it (`sh -c`, `CLAUDE_PROJECT_DIR` set,
  a hook payload on stdin): with `CLAUDE_PROJECT_DIR` a directory lacking
  `hooks/allow-repo-commands.sh` (a consuming repo's root) exits 0 with empty stdout and
  stderr and writes nothing; with it the vendored `agentTooling/` and with it a standalone
  checkout, the payload `python3 -c 'print(1)'` is denied. A `self/tests` script asserts
  these offline, and that `--check` reports in-sync in a standalone checkout.
- `--check` fails, naming the exact regenerate command, on a missing or drifted file; in a
  vendored copy it writes nothing under `--write` and its `--check` verdict is sensible and
  documented.
- Consumers: the non-`--self` merge output of `wire-settings.py` is unchanged
  (`self/tests/hook-wiring.sh` green); nothing a consuming repo loads at its root changes.
- No other feature's directory under `self/features/` changed (`git diff main --
  self/features` shows only `self-cloud-bootstrap/`).
- `self/tests/self-settings.sh` is green with `GATE_RESUME=1` in the environment.
- No residue of the round-1 bootstrap: no `BOOTSTRAP_COMMAND`, no `settings.local.json`
  generation, no doc still describing a SessionStart bootstrap as the design (except as the

- Docs current: `hooks/README.md`, `self/README.md`, `self/tests/README.md`,
