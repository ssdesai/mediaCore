# Release contract: the `mediacore` package and the IT'S SAXY fixture

WP0 of the cross-repo integration (`INTEGRATION.md` §12). Delivers the whole contract
package: the neutral `Release` schema (§3), authority-keyed refs and provenance (§4),
the shared `normalize_text` / `normalize_catno` fold, the bundle reader/writer (§5),
and the *IT'S SAXY* contract fixture (§11) with the deterministic script that generates
it. Nothing else in the repo — no app code, no database, no TypeScript. vinylCatalogue
(WP1) and both consumers (WP2, WP3) are blocked on the tag cut from this branch.

Tests are grouped as three plans rather than one per file
(`AGENT_PLANS.md` → "Splitting tests plans"): `test_normalize.py` and `test_refs.py`
are 55–90 lines each and share every pinned fact, so they run as one session; the
larger `test_release.py` and `test_bundle.py` get one each. Four separate sessions for
the small pair would each pay a fresh cache-creation charge (~$0.27) to run five turns.

**Build executors have no bash, so no build plan can produce the fixture's files.**

`fixtures/its-saxy/` are first written when the level-2 gate's `fixture idempotent`

say so, and none of them may create a file under `fixtures/its-saxy/`.

## Deliberately excluded

- **No adapter, no consumer code.** `Record → Release` is WP1 (vinylCatalogue); the
  import pages are WP2/WP3. Nothing vinyl-shaped may enter `src/` — `"vinyl"` is one
  value of `Medium`, and the code that chooses it lives in the other repo.
- **No `isrc` / `barcode` ref constants.** §4's table lists them, but neither matches
  the ref-key grammar the same section states (both lack an `<entity>` segment), and
  both are marked *reserved*. The grammar is implemented verbatim and the two keys are
  left undefined rather than invented as `isrc:recording` / `barcode:release`; the
  contradiction is recorded in `src/mediacore/README.md` for the owner to settle.
  Plan 01's assertions never touch them, and `tests/test_refs.py` pins them as
  *invalid* keys under the grammar as written — narrowed at authoring time so the final
  gate is not red by construction.
- **No `GET /api/resolve`, no ref-URI consumers.** §10, phase 2. `ref_uri` /
  `parse_ref_uri` ship because §4 specifies them; nothing calls them yet.
- **No real media in the fixture.** §11 settles this: placeholder PNG/WAV bytes so the
  hashes are reproducible. The fixture's `sha256`s deliberately differ from the live
  record's.
- **No `LICENSE`, and no tag.** `v0.1.0` is cut by the owner after this PR merges (§12).
